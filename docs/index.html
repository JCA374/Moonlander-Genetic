Landing on the Moon with 36 numbers

A genetic algorithm (CMA-ES) evolves a tiny linear controller that lands Gymnasium's LunarLander. It uses no neural network and no gradients, just a population of pilots that gets better every generation.

1The problem

The lander starts high above the surface with a random push. It has to touch down softly between the two flags. Gravity pulls it down, and every engine burn costs fuel.

The lander observes 8 numbers……and picks one of 4 actions
x, y position · horizontal & vertical velocity · angle · angular velocity · left / right leg contact 0 do nothing · 1 fire left engine · 2 fire main engine · 3 fire right engine

2The controller: one matrix multiplication

scores = state @ W + b   # W: 8×4, b: 4
action = argmax(scores)

Each of the 8 inputs votes for each of the 4 actions through one weight. The action with the highest total fires. That makes 8 × 4 weights + 4 biases = 36 parameters.

This is linear_controller.py. The policy itself is a few lines of code. All the intelligence lives in the 36 numbers, and finding good values for them is the genetic algorithm's job.

3Evolution: a population of pilots

Training never computes a gradient. Each generation it:

  1. Samples 50 candidate controllers, each a vector of 36 numbers.
  2. Evaluates each by flying 10 episodes and computing a fitness score.
  3. Selects the best half.
  4. Updates where the next generation is sampled from.

At generation 0 every pilot is random and they all crash, though some crash less badly than others. That ranking is all the algorithm needs.

4Inside CMA-ES

Covariance Matrix Adaptation Evolution Strategy is a modern evolutionary algorithm. Instead of crossover and bit-flips, it keeps a search distribution (a Gaussian cloud) over the 36-dimensional parameter space and keeps reshaping it.

  • Mean: moves toward the best-ranked candidates (weighted by rank).
  • Covariance: stretches along directions that kept producing improvements, so the cloud learns the shape of the landscape, such as a long diagonal valley.
  • Step size σ: grows while progress is steady and shrinks near an optimum.
The picture is a 2-D toy problem so you can see the cloud. On the real task the same thing happens in 36 dimensions. cma_es_optimizer.py wraps the cma package and falls back to a simple GA if it isn't installed.

5Fitness: what "good" means

fitness = average_reward
        + 100 × landing_rate
        + 30 × (1 − avg_steps / 1000) × landing_rate   # speed bonus, only when landing

The environment's reward already penalises fuel and crashes and rewards soft touchdowns. The extra terms make landing the overriding goal and then favour quick landings. This is the default balanced mode. --fitness-mode also offers standard, speed and fuel.

6Results

200 generations × 50 pilots × 10 episodes (100,000 episodes in total) took about 6 minutes on an 8-core CPU (--parallel 8).

Within roughly 40 generations the best pilots go from crashing to landing. By the end, the population average (blue) is close to the best, so nearly every sampled pilot can land.

The same starting conditions, flown by checkpoints from different generations. Early pilots fall or spin away. Later ones hover, then steer toward the pad and land.

7What it learned

A linear pilot can be read directly. For example, vertical velocity → main engine has a large negative weight. The faster the lander falls (negative velocity), the higher the main-engine score, so it brakes harder the faster it drops.

Try it yourself:

python play_ga.py --model ga_models/ga_best.npy --describe

8Run it yourself

# setup
git clone https://github.com/JCA374/Moonlander-Genetic && cd Moonlander-Genetic
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# evolve a pilot (a few minutes on a multi-core CPU)
python train_ga.py --parallel 4

# watch it, evaluate it, plot it
python play_ga.py --model ga_models/ga_best.npy --episodes 5
python play_ga.py --model ga_models/ga_best.npy --evaluate 100 --no-render
python plot_ga_training.py --history ga_models/training_history.json

# regenerate this page's video from your own run
python video_tools/make_explainer.py
